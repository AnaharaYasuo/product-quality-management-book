# 書籍執筆・品質確証スキル（book-authoring）

本スキルは、書籍『プロダクト品質管理の実践ガイド（AI時代のプロダクト・プロセス確証バイブル）』の各章を執筆・レビュー・検証する際に使用する専用スキルです。

---

## 1. 執筆時の必須チェックリスト（Commercial DoD Validator）

各章の原稿を作成またはレビューする際、以下の基準を厳格にチェックしてください。

### ① ボリューム・密度チェック
- [ ] 文字数: 該当Markdownファイルの文字数が **8,000文字〜12,000文字** の範囲内にあるか（概要まとめ・薄い箇条書きは不可）。

### ② ダイアグラム（Mermaid）チェック
- [ ] 概念や構造を可視化するMermaid図が **最低2点以上** 含まれているか。
  - 推奨形式: `flowchart TD / LR`, `sequenceDiagram`, `stateDiagram-v2`, `classDiagram`

### ③ 現場実践コード・プロンプトチェック
- [ ] 読者がコピペして即座に動かせる実践成果物が **最低2点以上** 含まれているか。
  - 例: テストコード（Jest/Pytest/Playwright）、CI設定（GitHub Actions YAML）、プロンプト設計、設定ファイル等

### ④ アンチパターン対比チェック
- [ ] 「現場でやりがちな失敗事例・形骸化」と「その処方箋（改善アプローチ）」が明確に対比されているか。

### ⑤ QA合否判定基準（Pass/Fail Criteria）チェック
- [ ] 該当工程・成果物において、「何を満たせば合格（マージ可・出荷可）とし、何が起きたら不合格（差し戻し・ブロック）とするか」の決定論的基準が明記されているか。

### ⑥ 章末ワークショップチェック
- [ ] 読者が翌日自チームで実践できる「セルフアセスメントシート」または「演習課題」が末尾に配置されているか。

---

## 2. 執筆ワークフロー（SDD準拠）

1. **対象Issueの確認**:
   - `gh issue view <No>` で該当章の背景、セクション構成、満たすべきQA観点を確認する。
2. **作業ブランチの作成**:
   - `git checkout -b feat/issue-<No>-<title>`
3. **原稿の執筆**:
   - `manuscript/<No>_<chapter>.md` を作成または編集。
4. **セルフレビュー（本スキルのチェックリスト実行）**:
   - 文字数、図解、コード、アンチパターン、合否基準、章末課題を網羅しているか検証。
5. **ローカルビルド検証**:
   - 構文エラーやEPUBレンダリング不備がないことを確認。
6. **PR作成**:
   - `main` 宛てにPRを作成（`Closes #<No>`）。PR本文にセルフチェック結果を明記。
