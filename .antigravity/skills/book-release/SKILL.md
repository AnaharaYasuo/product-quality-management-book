# 書籍版管理・リリース運用スキル (`book-release`)

## 目的
書籍（KDP / 商業出版 / 同人誌など）の執筆・出版において、版（刷数や改訂履歴）と成果物（EPUB / PDF）を安全かつ永続的に管理するための標準フロー。

## 原則
1. **GitHub Actions Artifacts は一時的な検証用**（デフォルト90日で失効）。入稿・出版用の確定データ置き場にしてはならない。
2. **GitHub Releases は確定成果物の永続保存庫**。Gitタグと紐付けて、どのコミット（原稿状態）から生成されたデータかを100%追跡可能にする。
3. **改訂履歴（Changelog）と正誤表（Errata）** をリリースページに必ず明記する。

---

## バージョニング設計基準

| バージョン形式 | 出版における意味 | 例・トリガー |
| :--- | :--- | :--- |
| `v0.x.x` | 執筆・プレリリース | `v0.1.0-alpha` (初稿), `v0.9.0-rc.1` (校正用) |
| `v1.0.0` | **第1版 第1刷** | KDP初回入稿・初回印刷データ確定時 |
| `v1.0.x` | 軽微なパッチ修正 | 誤字脱字、URL修正、レイアウト崩れの緊急修正 |
| `v1.x.0` | **第1版 第N刷（重版）** | 重版修正、追加の小コラム追加、データ更新 |
| `v2.0.0` | **第2版** | 章の全面改訂、章の追加・削除など大幅なアップデート |

---

## リリース手順フロー

1. **原稿の最終チェック**:
   - `production` ブランチにすべての確定原稿がマージされていることを確認。
   - CIによるプレビュービルド（Artifacts）で目視確認を行う。

2. **Git タグの付与とプッシュ**:
   ```bash
   git checkout production
   git pull origin production
   git tag -a v1.0.0 -m "第1版 第1刷 リリース"
   git push origin v1.0.0
   ```

3. **GitHub Release の生成**:
   - ワークフローにより自動生成、またはGitHub CLI / Web UIから作成。
   - 添付アセット:
     - `product-quality-management-v1.0.0.epub`
     - （PDFがある場合）`product-quality-management-v1.0.0.pdf`
   - 本文（リリースノート）のテンプレート:
     ```markdown
     ## 版情報
     - 版数: 第1版 第1刷
     - 対象コミット: <commit hash>
     - 制作環境: Pandoc / GitHub Actions

     ## 主な変更点 / 概要
     - 初版公開

     ## 正誤表・差分
     - 特になし
     ```
